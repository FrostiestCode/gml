C++ API

The mod-facing surface is a pure C ABI made of versioned structs. This page is the map: entry points, result codes, types, and every sub-API with its current status. The headers remain the authority.

Current ABI: GML_ABI_VERSION 0x00010000 (1.0.0). Include <gml/GML_Mod.h> and link GrappleModLoader.lib. Sub-APIs are appended, fields are appended, and older loaders leave unknown pointers NULL.

Getting the API

#include <gml/GML_Mod.h>

static int OnInit(const GML_ModContext* ctx)
{
    const GML_Api* api = ctx ? ctx->api : nullptr;
    if (!api || !api->core) return GML_ERR_ABI;

    // Null-check every sub-API you did not verify at compile time.
    if (!api->console) return GML_ERR_UNAVAILABLE;

    api->core->LogLine(GML_LOG_INFO, ctx->modId, "hello from my mod");
    return GML_OK;
}

GML_MOD_ENTRY(OnInit)

Outside the entry point, call GML_GetApi(sizeof(GML_Api)). If a newer mod asks for a larger struct than the loader knows, the loader returns a zero-padded copy, so extra fields read as NULL instead of running off the end.

Vehicle

The shape is defined — IsAvailable, GetCurrent, IsPlayerInVehicle, position/velocity/direction, health, boost and speed — but the vehicle signatures are not mapped on this build. Calls return GML_ERR_NOT_RESOLVED. Vehicle teleport specifically fails because the interaction-context chain used on foot is absent while driving.

Entity

MethodNotes
IsAvailable / IsValid / GetId / GetTypeNameAvailability follows the signature database.

GetCount / GetByIndexBridges to world iteration; world signatures are unresolved.

World

IsLoading, time of day, weather, active region, entity count, raycast and map marker are defined and degrade honestly. No World::* signatures are recorded yet, so expect GML_ERR_NOT_RESOLVED.

Status at a glance

AreaState on the recorded build
Core, memory, hooks, events, consoleImplemented Loader-side; no game signature required.
Player position and healthVerified
Prop spawnVerified Async handles recorded.
Content / archive accessImplemented Testable today.
Signature inspection and debugImplemented
Vehicle, world, entity destroyUnresolved Returns GML_ERR_NOT_RESOLVED.

Do not treat GML_ERR_NOT_RESOLVED as a transient failure. It means the feature is deliberately unavailable until someone researches its signature on this build and proves it in game. Guessing an address is how a mod turns a missing feature into a crash.
