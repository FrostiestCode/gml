Roadmap

What works, what is open with concrete leads, what is merely planned, and what is deliberately out of scope. Everything in "working" has been demonstrated in game on this build. There are no ETAs — this is a personal loader project.

Working now

01

Loader chain

dinput8.dll proxy → GML.Core → four sample mods, all hot-reloadable.

02

Console and overlay

In-game console (`), external console, transparent overlay, scrollback, help.

03

Input gating

DirectInput neutralised, GetCursorPos frozen, window messages swallowed while panels are open.

04

Player chain

GetPosition / SetPosition / GetHealth through the public API.

05

Teleport that sticks

tp.set x y z through the interaction-context world matrix — the engine keeps the new transform.

06

Prop spawn

By model name; asynchronous handles recorded and listed by prop.status.

07

Spawn menu

Numpad 0. A 795-name catalog in a fresh session — 195 vehicles, 84 weapons, 516 misc — sorted, source-tagged and growing via runtime harvest.

08

Borderless window

F11 toggle with exact style/rect save and restore, per-monitor.

09

Signature database

Build-keyed, verify-checked entries; unknown builds degrade to GML_ERR_NOT_RESOLVED instead of crashing.

10

Crash handler

Minidumps plus a report written beside the logs.

Open — with leads

ItemLead
Entity::Destroy / prop.destroy Engine console commands despawn.chars / despawn.cars are registered at 0x140DF4CE0 (name strings at 0x1424AB788 / 0x1424AB798). Objects are held by boost::shared_ptr with an SGameObjectDestroyer deleter, and a CDespawnPool reacts to Havok body removal. Full notes: RE_PLAYER_CHAIN.md §9.6.
Vehicle teleport While driving, the character's interaction chain is absent; it runs only while attached. Watchpoint the vehicle's applied transform and walk up to its source, the same way the character teleport was found.
Player::GetVelocity / aim / grapple state Shape searches exist (tools/find_getters.py); player object offsets are already mapped by SigHunter's probe.
Spawn-menu search box The panel is keyboard-driven; a type-to-filter line over the current category is the obvious next UX step.
Mouse selection in the spawn menu The overlay has no cursor yet; needs a drawn cursor plus hit testing in the Present pass.
Spawn-at-crosshair Find the aim position on this build (likely a CSteeringPlayer field) and offer "spawn where I look".
Weapon-in-hand from the menu Spawning a weapon object is not equipping it; needs the inventory/equip path, not researched yet.

Ideas (not started, no promises)

  • Lua scripting layer (GRAPPLELUA) — only if someone needs it beyond what console commands already cover. The C ABI is the stable surface.
  • World editor — would first need World::* signatures (streaming, weather, time of day), all unresolved today.

Non-goals

  • Multiplayer anything.
  • Supporting exe builds other than the one installed here without re-research per entry (the signature system is the mechanism; someone has to do the work per build).
  • Patching game code pages for gameplay changes — hooks are for observation and input; transforms go through data.

No promises. This page reflects one person's work on one exe build, not a product roadmap. Features marked unresolved will stay that way until someone researches a signature and proves it in game.

Source: docs/ROADMAP.md. Verified against build 0x5787641C.
