FEATURES // VERIFIED IN GAME

What works today.

Everything on this page was demonstrated on the recorded Just Cause 3 build unless it is marked otherwise. Unresolved features say so — GML never guesses an address to make a feature look finished.

Build key. Verified against SizeOfImage 0x3241000 and TimeDateStamp 0x5787641C. On any other exe, keyed signatures refuse to resolve and dependent calls return GML_ERR_NOT_RESOLVED instead of running against the wrong bytes.

Verified feature set

FeatureStateWhat it does
Local player chain Verified CNetworkPlayerManager → CCharacter. Position and health are reachable through the public API.
Teleport that sticks Verified tp.set x y z writes through CInteractionContext+0x330; the engine re-derives its own transform, so Rico stays put.
Prop spawn Verified CSpawnSystem::Spawn is asynchronous; GML records the handle and prop.status reports it.
Spawn menu Verified Numpad 0 opens a GMod-style browser for vehicles, weapons, characters, animals and props.
Runtime model harvesting Verified Names are harvested from the game's own streaming while you play; the catalog grows instead of staying frozen.
Console and overlay Verified Transparent in-game console with scrollback, plus an optional external Win32 console for a second screen.
Input gating Verified While a panel is open, DirectInput reads are neutralised and GetCursorPos is frozen. Typing never moves Rico.
Mod hot-reload Verified gml.mod reload tears down a mod's hooks, events and commands through the DispatchGate before loading the new DLL.
Borderless window Verified F11 saves the exact window style, switches to borderless, and restores the original style on toggle back.
Per-object destroy Unresolved Entity::Destroy is not mapped yet. prop.destroy exists but needs research.
Vehicle teleport Unresolved The interaction-context chain used for tp.set is absent while driving. No value is invented in its place.

Closing a panel returns input to the game. The gate covers both keyboard and mouse, so console typing and menu navigation do not leak into gameplay.

Inside the spawn menu

A fresh session lists 795 names: 195 vehicles, 84 weapons, and 516 misc entities (characters, animals, props, wrecks and DLC). Every entry carries its source in the menu footer:

SourceWhere it comes from
verified126 vehicle and 24 weapon names whose Avalanche hashlittle hash GML reproduces exactly, from re-verified jc3-api tables.
runtimeNames harvested live from the game's streaming: characters, animals, props, wrecks and DLC entities. The list grows while you play.
dropzoneFile stems of loose .ee entity mods in <game>\dropzone\.
userOne name per line from GrappleModLoader\spawnmenu\*.txt. A starter models.txt is created for you.

Categories are inferred from the name: v<digits>_ becomes Vehicles, w<digits>_ becomes Weapons (including the dlc*_ prefix). Other harvested names go to Misc; anything unclassifiable lands in Unknown. gml.spawnmenu dump writes the whole catalog to catalog_dump.txt.

Engineering rules

  1. No address is trusted without a signature that matches this exe build and byte-verifies at load.
  2. Unresolved features return GML_ERR_NOT_RESOLVED and say so. They never guess.
  3. Every game call is SEH-contained in exactly one place.
  4. Offsets transcribed from third-party layouts are hypotheses until a runtime check agrees.
  5. No fabricated content: model names come from verified tables, game memory, your dropzone, or your own lists.
